# Walk in Light

A personal progress console for building the **Walk in Light** media universe: a three-film story, educational YouTube series, and Christian-worldview reviews of anime and film. Cyberpunk pixel art, heavy neon, a cross at the center.

It is a free, installable web app (PWA) for iPhone. No App Store, no developer account, no server, no cost. All data stays on the phone.

## Install on your iPhone (free)

1. Host the files (see **Hosting** below). You get a URL like `https://<you>.github.io/<repo>/`.
2. Open that URL in **Safari** on the iPhone.
3. Tap **Share** → **Add to Home Screen** → **Add**.
4. Open it from the home screen. It runs full screen and offline.

Your progress lives in the app's local storage on that phone. Export a backup from **Settings** once a month; it uses the iOS share sheet so you can save straight to Files or Drive.

## Hosting (GitHub Pages, free)

This folder is a static site. In the repository: **Settings → Pages → Build and deployment → Source: Deploy from a branch**, then pick the branch and `/ (root)`. GitHub prints the URL a minute later.

Public repositories get GitHub Pages for free. A private repository needs a paid plan for Pages, so keep the repo public (there is nothing private in the code; your data never leaves the phone).

### Moving this into its own repository

Everything the app needs is in this folder tree. To give it its own home:

```
git clone <this repo> && cd <this repo>
git checkout claude/walk-in-light-app-gr3i7l
# create an empty public repo called walk-in-light on GitHub, then:
git remote add wil https://github.com/<you>/walk-in-light.git
git push wil claude/walk-in-light-app-gr3i7l:main
```

Then enable Pages on the new repo as above.

## What is inside

|---|---|
| `index.html` | App shell |
| `js/seed.js` | **All the content**: pillars, milestones, step-by-step guides, pipelines, story bible drafts, playbook, verses. Edit this to change the starting content. |
| `js/app.js` | App logic: state, rendering, XP, streak, inbox, export/import, reminders |

| `sw.js`, `manifest.webmanifest` | Offline cache and install metadata |
| `icons/` | Pixel-art icons, generated by `tools/make_icons.py` |
| `docs/` | Story concept, solo-creator playbook, open questions |

## How the app is organised

- **Home**: verse of the day, Light level (XP) and streak, the *I have 15 / 45 / 90+ minutes* filter, **Next up** (one task per pillar), the idea **Inbox**, pillar progress.
- **Story** (The World): the steps for theme, world, characters, trilogy architecture, shorts, organisation; a **Scripts** pipeline (Premise → Locked) for the three films and shorts; the **Bible** (characters, locations, factions, lore, events, themes, props).
- **Teach**: series design, then the full blueprint for a first branded video (pre-production, production, post, publishing, review and repeat) and an **Episodes** pipeline.
- **Lens**: the four-question worldview framework, format and script template, producing review #1, cadence; a **Reviews** pipeline.
- **Base** (Foundation): mission, rule of life, brand umbrella, accounts and folders, backups, legal and money basics.
- **📖 Playbook**: solo-creator best practices. **⚙ Settings**: glow, text size, calendar reminder, export/import, content merge, reset.

Every task has a size (S 15 min, M 45, L 90+), a "how to do it" guide, your notes, and can be pinned as the week's focus. Tapping the box cycles todo → doing → done.

## Updating content later

Edit `js/seed.js`, bump `version`, bump `CACHE` in `sw.js`, push. On the phone, **Settings → Merge latest content** adds the new steps and refreshes guides on steps you have not edited, keeping all progress.

## Reminders

iPhone web apps cannot schedule their own notifications without a push server. **Settings → Add daily reminder** generates a repeating calendar event with an alert; or set a daily reminder in the iOS Reminders app. See `docs/QUESTIONS.md` for the options if you want real push notifications.
